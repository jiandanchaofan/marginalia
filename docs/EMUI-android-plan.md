# 墨边 · 华为 EMUI（Android）版方案

状态：**已规划，暂缓，尚未开始实现**。写于 2026-11，对照当时的代码；动手前先核对一下"现状"一节是否还成立。

目标：把墨边做成可以装在**华为 EMUI（AOSP 12 及以上）**手机上的应用，**不依赖任何 Google（GMS）或华为（HMS）服务**。用 Tauri 2 的 Android 支持，网页界面和大部分 Rust 代码复用。

## 结论

可行。Tauri 2 正式支持 Android；笔记库（`notes.rs`）、待办与目标（`tasks.rs`）、笔记回顾（`review.rs`）、回收站（`trash.rs`）、订阅（`feeds.rs`）、剪藏（`web.rs`）、书中文字索引（`bookindex.rs`）都是平台无关的 Rust，可以直接复用。

**不适用的情形**：HarmonyOS NEXT（5.0 以上）不兼容 Android 应用。如果手机是这类系统，要另做鸿蒙版（网页部分可以复用，原生部分重写）。

## 现状（2026-11 检查）

**有利的**
- Rust 部分已按手机做了准备：入口带 `#[cfg_attr(mobile, tauri::mobile_entry_point)]`；单实例（`tauri-plugin-single-instance`）和开机启动（`tauri-plugin-autostart`）只在桌面编译；网络用 `rustls` 而不是 OpenSSL；SQLite 是 `bundled`，都能交叉编译到安卓。`windows-sys` 只在 Windows 编译。
- 界面已有窄屏模式：页边笔记收成底部抽屉，各页侧栏在窄屏变抽屉（`hub-side.open`）。
- 不依赖外部字体服务：英文字体 Source Serif 4 / Literata 已打包；中文衬线在安卓上通常落到 Noto Serif CJK SC（字体栈已包含）。

**缺的环境**
- 本机有 Android Studio 和 SDK（`%LOCALAPPDATA%\Android\Sdk`，含 platforms / build-tools / emulator / system-images）。
- 缺：Android NDK、`JAVA_HOME`、Rust 的 Android 目标（目前只有 `x86_64-pc-windows-msvc`；至少需要 `aarch64-linux-android`）。

## 最大的风险：华为的系统 WebView 偏旧

华为没有 GMS，系统 WebView 更新慢，EMUI 12 / 13 的版本不固定（可能是 Chrome 9x 到 11x）。代码里用到的较新特性：

| 特性 | 位置和数量 | 需要的 Chrome |
|---|---|---|
| `color-mix()` | CSS 里约 154 处 | 111 |
| `:has()` | CSS 里 2 处 | 105 |
| `Promise.withResolvers` | pdfjs-dist 6 | 119 |
| `backdrop-filter` | CSS 里 17 处 | 76（需 `-webkit-` 前缀的另算） |
| ES2022 | Vite 构建目标 `es2022` | 94 |

对策：
1. 构建时用 PostCSS 插件把 `color-mix` 展开成固定颜色，`:has()` 改写成不依赖它的写法。
2. 降低 Vite 的 JS 构建目标，补必要的垫片。
3. PDF 改用 `pdfjs-dist/legacy`（需要补 `Promise.withResolvers` 等）。
4. **必须用真机验证**：模拟器的 WebView 不能代表华为的。

## 分阶段计划与工作量估算

| 阶段 | 内容 | 估算 |
|---|---|---|
| **A 打通** | 装 NDK / Java / Rust 安卓目标；`npm run tauri android init`；模拟器和真机上跑出界面 | 1~2 天 |
| **B 兼容** | WebView 特性审计和降级（上表）；构建目标调整；真机逐页检查样式 | 2~4 天 |
| **C 能用** | 见下 | 5~8 天 |
| **D 联网** | 订阅更新、网页剪藏在手机上的验证；接收系统「分享到墨边」 | 3~5 天 |
| **E 发布** | 图标、启动图、签名、体积优化，产出可安装的 APK（约 15~25MB） | 1~2 天 |
| **合计** | | 约 **3~4 周**的集中工作量，不含真机反复调试的往返时间 |

### C 阶段（能用）要做的事

- **导入文件**：手机选到的是 `content://` 地址，现有的 `import_book`（用 `std::fs` 读路径）读不了。改走系统文件选择器加 `tauri-plugin-fs`，大 PDF 要分块读，在 Rust 里按块写入书库。
- **返回键**：关面板、回上一层、回书架（`@tauri-apps/api/app` 的返回键事件）。
- **选字**：长按选字时系统工具条会和墨边自己的颜色工具条冲突，要把自己的工具条放到选区下方。
- **安全区域**：刘海、手势条的边距（`env(safe-area-inset-*)`，视口加 `viewport-fit=cover`）。
- **无鼠标的交互**：
  - 悬停才出现的小图标要常驻显示。
  - 拖拽（任务拖到菜单、关系图拖卡片）要有触摸替代方案；关系图在手机上先用列表。
  - Ctrl+K 命令面板要有触摸入口（一个搜索图标）。
  - 触摸目标不小于约 44px。
- **桌面专属功能要隐藏**：桌面卡片、托盘、开机启动、键盘快捷键设置、窗口缩放（`setViewZoom` 在手机上要换成页面缩放）、右键菜单限制（无影响）、Ctrl+N 小窗口（改成按钮触发）。
- **桌面版「原始网页」**另开窗口（`openWebWindow`），手机上要改成应用内全屏页。
- **备份**：现在备份到用户选的文件夹，手机上要改成"导出到下载目录或系统分享"。
- **书中文字索引**：手机上默认关闭（耗电、发热），可手动开启。

### D 阶段（联网）

- 订阅和剪藏的网络层（`reqwest` + `rustls`）本身可用，需要验证证书和代理。
- **接收分享**：写一小段 Kotlin，接收 `ACTION_SEND`（`text/plain`）的分享（微信、浏览器分享网址 → 剪藏）。桌面版靠 `marginalia://clip` 书签，手机上改走 Android 分享菜单；Tauri 的深度链接插件可以作为补充。

## 我能做的和不能做的

- **我能做**：环境配置、代码改造、模拟器调试、产出 APK。
- **我不能做**：真机测试。每次改动需要装到手机上看，把结果反馈回来。进度快慢很大程度取决于这个来回的次数。

## 建议先做一次小范围试验（1~2 天）

只做 A 加 B 的最小部分：打一个调试 APK，装到真机，打开一本 EPUB 看能不能读。这样最快能确认**手机的 WebView 版本**和**界面基本能不能正常显示**，比估算可靠得多，之后再决定要不要继续、怎么排期。

## 动手前要先确认的三件事（尚未回答）

1. **手机型号和系统版本**：EMUI 12 / 13，还是 HarmonyOS 几？（决定方案是否适用）
2. **有没有真机可以 USB 调试**？
3. **自用还是分发给别人**？自用直接装 APK；上架华为应用市场需要开发者账号，国内还涉及软件著作权，暂不考虑。

## 发布方式

- 自用：debug 或自签名 release 的 APK，直接传到手机安装。
- 分发：APK 加签名，托管下载；不依赖任何应用商店。

## 与其他计划的关系

- **云同步**（方案讨论中）是手机版真正有用的前提：手机和电脑要看到同一份书、笔记和待办。
