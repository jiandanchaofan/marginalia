# 查词典（MDict）· 方案与进度

决定（2026-11-16，与用户确认）：

- **触发**：选中文字后工具栏里多一个「查字典」；双击一个词自动弹出词典卡片；Ctrl+K 里加「查词」命令，输入英文词直接查。
- **词典**：用户自己的 MDict（.mdx 和 .mdd），英英、英汉等；先做 MDict，之后再考虑 StarDict、DSL。词典文件**不复制进软件**，只记路径；索引在本机，不上传。
- **显示**：卡片里多本词典分页；释义在受限框架里显示（默认不执行脚本、不加载远程资源，样式、图片、发音来自 .mdd），**自动判断这本词典是否需要脚本**，需要才打开；保持词典自带样式的美观。
- **摘录到笔记**：把「词 + 简短释义」存成一条笔记，锚定在选中位置，带 `#词汇` 标签。
- 它是**核心功能**，不是插件。

## 读 MDict 的方式（`src-tauri/src/mdict.rs`）

文件不整本读入：打开时只读头部和每个词条索引块的首尾词；查词时二分定位到块，解压那一块，再解压装着这条的记录块。几百 MB 的词典也是毫秒级。支持版本 1.2 和 2.0，块压缩 zlib / LZO / 不压缩，词条编码 UTF-8 / UTF-16 / GBK / GB18030 / Big5，索引加密（不需注册码的那种）。**不支持**：需要注册码的、MDict 3.0 的，遇到会明确说明原因，不会崩溃。

- 比较词条时不分大小写，默认忽略标点和空格（词典头里 `StripKey`）。
- `@@@LINK=词` 重定向会自动跟随。
- 前缀匹配用来做「相近的词」建议。
- .mdd 里的文件（样式、图片、发音）按 `\路径\文件名` 取出。

## 用真实词典验证

```
cd src-tauri
$env:MDX_FILE = "D:\词典\xxx.mdx"      # PowerShell
cargo test --release real_dictionary -- --ignored --nocapture
```

会打印词典标题、版本、编码、词条数，以及 hello、the、run、ran、ephemeral、apple、set、你好 等词的查找结果和耗时。只读文件，不修改、不上传。

## 用真实词典验证的结果（2026-11-16）

用户的两本词典：《牛津高阶英汉双解（第10版）》（.mdx 61 MB，31 万词条；5 个 .mdd，共约 2.2 GB：图片和样式、英式发音、美式发音、另两组发音）和 COCA Frequency 60000（.mdx 2 MB，5.4 万词条，旁边有同名的 .css 和 .js）。

- 都能打开，**打开约 2–20 毫秒，查一个词 2–5 毫秒**（调试版；牛津的「run」一条有 13.8 万字符也是毫秒级）。
- 牛津词典的词条顺序不是「小写、去标点」，而是「只小写」，一开始被当成无序，第一次查词要把 31 万词条全读一遍（约 0.9 秒）；现在会依次试几种排序方式，找到合适的，不用整本读。
- 5 个 .mdd 都能读：第 1 个是样式、脚本、图片（`oald10.css` 186 KB、`oald10.js`、`am/antelope.png`），其余是发音 mp3。**一本词典的资源分在几个 .mdd 里，要全部打开、依次查找**：`name.mdd`、`name.1.mdd`、`name.2.mdd`……
- 词条里的链接：`<link href="oald10.css">`、`<script src="oald10.js">`、`sound://hello__gb_1.mp3`、`entry://greeting`（点了在卡片里再查）、`entry://@ox3000&level=a1`（词典自己的内部链接）。
- COCA 的词条引用 `coca.css`，而旁边的文件叫 `COCA Frequency 60000.css`：**资源在 .mdd 里找不到时，要回退到词典文件旁边同扩展名的文件**。
- 两本词典的词条里都有脚本引用，第二阶段显示时按「只允许这本词典自己的脚本、放在隔离的框架里」处理。

验证用的两个测试只在设置了环境变量时才运行（`MDX_FILE`、`MDD_DIR`），词典文件的路径不进仓库。
